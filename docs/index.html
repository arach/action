What it is

Not just screen recording.

Action is a runtime where a human or an agent can stage a scene, run deterministic actions, and produce machine-readable output with every capture.

Action.app

Signed AppKit host. Owns permissions UX, WebKit console, recording-probe lifecycle, and the supervision overlay.

agent runtime

Local orchestration process for transport, automation-facing methods, and agent-to-app coordination.

session artifacts

Every capture produces raw media, structured trace data, screenshots, and a finished marker file.

The loop

One tight cycle.

Action is organized around a single repeatable loop you can run manually or drive with an agent.

01

Launch and stage

Start Action.app, open the embedded console, and set up the scene you want to capture.

02

Run a guided capture

Use action-dev host <scenario> to start a recording probe. The probe runs in a fresh app instance for clean, deterministic output.

03

Review in-app

The session library surfaces the playable artifact plus trace data. Completion is marker-based, not response-based — the artifact is authoritative.

04

Hand off

Leave machine-readable feedback or pass the artifact directly to an editor, composer, or downstream agent.

Developer CLI

One alias, all commands.

The repo-local CLI covers the full build and runtime loop.

action-dev
$ alias action-dev='bun packages/cli/src/action-dev.ts'
$ action-dev build
$ action-dev relaunch
$ action-dev doctor
$ action-dev hud
$ action-dev logs

Requirements

What you need.

  • macOS on Apple Silicon
  • Bun (package manager and script runner)
  • Xcode command line tools or a full Swift toolchain
  • Accessibility and Screen Recording permissions granted on first launch
